# Performance and Architecture – Fastify Interview Guide

This page focuses on performance characteristics, architectural decisions, and design patterns for real-world systems.

---

## 16. Why is Fastify considered fast?

Fastify is optimized to reduce overhead in request processing. Its architecture is designed for low-latency and high-throughput APIs.

### Main reasons
- Efficient routing
- Optimized JSON serialization
- Lightweight internal design
- Schema compilation and validation reuse

---

## 17. How would you benchmark a Fastify service?

A senior engineer would benchmark latency, throughput, CPU use, and memory under realistic load.

### Common tools
- `autocannon`
- `wrk`
- `k6`

```bash
npx autocannon http://localhost:3000/health
```

### What to measure
- p50, p95, p99 latency
- requests per second
- memory usage
- error rate

---

## 18. How do you scale Fastify applications?

Fastify services should be designed to be stateless and horizontally scalable. Use load balancers, container orchestration, and external caching where required.

### Senior pattern
Keep session state external and avoid coupling service instances to local memory.

---

## 19. How do you manage configuration in Fastify?

Configuration should be externalized and injected through environment variables or config modules.

```js
const config = require('dotenv').config();
```

### Best practice
Do not hardcode secrets or environment-specific values inside business logic.

---

## 20. How do you implement dependency injection or shared services in Fastify?

Fastify uses decorators and plugins to expose shared services cleanly.

```js
fastify.decorate('userService', new UserService());
```

### Why this is useful
It makes code testable, modular, and easier to replace in future refactors.

---

## Interview takeaway
A senior Fastify engineer thinks beyond route creation and focuses on latency, scalability, and maintainable architecture.
