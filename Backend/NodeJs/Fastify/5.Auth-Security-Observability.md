# Authentication, Security, and Observability – Fastify Interview Guide

This page covers how a senior engineer would approach auth, security, and monitoring in Fastify.

---

## 21. How would you implement authentication in Fastify?

Authentication is usually implemented through a plugin and hooks. A common pattern is to validate a JWT in a pre-handler hook or a dedicated auth plugin.

```js
fastify.addHook('preHandler', async (request, reply) => {
  const token = request.headers.authorization;
  if (!token) {
    throw new Error('Unauthorized');
  }
});
```

### Senior view
Authentication should be centralized and reusable rather than duplicated in every route.

---

## 22. How do you secure a Fastify API?

Security measures include:
- Input validation
- Rate limiting
- Helmet-style headers
- Secure authentication
- Proper error handling
- Sensitive data protection

### Best practice
Treat validation and authorization as mandatory guardrails, not optional extras.

---

## 23. How do you add logging in Fastify?

Fastify supports logger configuration directly in the instance.

```js
const fastify = require('fastify')({ logger: true });
```

### Senior insight
Logs should be structured and should support tracing across requests and services.

---

## 24. How do you handle observability in production?

A senior engineer would integrate:
- structured logs
- metrics
- tracing
- health checks

### Why it matters
Without observability, performance problems and failures become much harder to diagnose.

---

## 25. What is a health check endpoint and why is it useful?

A health endpoint helps infrastructure monitor whether the service is alive and responsive.

```js
fastify.get('/health', async () => ({ status: 'ok' }));
```

### Senior perspective
Health checks should be lightweight and should reflect readiness as well as liveness where necessary.

---

## Interview takeaway
Security and observability are not separate from architecture; they are core parts of production-ready Fastify systems.
